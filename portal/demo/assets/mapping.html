Exactly what the API sends

POST /blueprint/api/blueprint-requests
{
  "blueprintId": "…",
  "projectId":   "…",
  "inputs": {
    "os":      "ubuntu",
    "size":    "small",
    "cluster": "linux-test",
    "zone":    "oa",
    "attributes": {
      "requester":   "kosten.yang@vsmc.local",
      "employeeId":  "A12345",
      "department":  "Information Technology",
      "ticket":      "REQ0012345",
      "purpose":     "test",
      "purposeNote": "MES interface testing"
    }
  }
}
The blueprint declares attributes as a single object and never names the keys inside it. A new field is one more key here and one more line in the portal's field definitions — the blueprint is untouched.
